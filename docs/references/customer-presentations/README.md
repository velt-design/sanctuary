# Customer Presentation Reference Access

The owner approved a design/feasibility proposal and a project partnership
booklet as presentation-quality references on 2026-09-11. The transferable rules
are in the [presentation standard](../../customer-presentation-standard.md).
[Design Booklets](../../design-booklets.md#presentation-refinement) owns the UI
application and remaining implementation work.

## Private Reference Boundary

This repository is public. The original client PDFs, rendered page previews,
customer-specific pricing, terms and the reference manifest remain in the
owner's local artifact workspace. Do not commit or push them, including in a
branch's earlier history. Presentation approval is not publication permission.

For work in the owner's artifact workspace, follow its local `AGENTS.md` pointer
to the retained reference library. It contains exact copies of the approved
PDFs, a manifest with SHA-256 hashes and page dimensions, and page previews.
The library is separate from these public source files and application assets.

In another checkout, use the written standard immediately. If visual matching
requires the examples, obtain access through the owner using an appropriate
private channel. Do not search for the client documents publicly or claim to
have inspected them when they are unavailable.

## Selecting A Reference

| Reference type | Pages to inspect | Transferable lesson |
| --- | --- | --- |
| Design/feasibility proposal | Hero, individual design directions, deliverables, fees and next steps | Explain why each direction suits the project, then make the measured design stage and its boundaries concrete. |
| Project partnership | Hero, involvement comparison and pricing comparison | Show the client's involvement and remaining amount payable as clearly as the contribution. |

Use approved examples for visual hierarchy, writing structure and client
comprehension. Take all customer identity, imagery, scope, figures and terms from
the new authorised brief. Do not infer client acceptance or content rights from
an attractive or owner-approved proposal.

Preserve private originals unchanged and version replacement approvals in the
private manifest. Public test fixtures should use neutral synthetic information.
